1   Executive Summary
CineStats is a modern, sleek, dark-mode-first interactive web dashboard that aggregates and 
visualizes box office and viewership data for films, film series, cinematic franchises, and TV series. 
Built on a Python + Streamlit stack, it is permanently free with no advertising and no paid tier.
The application is structured around four primary content types: individual Movies, Series & 
Franchises (multi-film sagas and cinematic universes), TV Series (tracked as a fully separate 
module), and Comparisons (up to 10 entities side-by-side). Each has its own dedicated tab and 
detail view in the sidebar.
CineStats delivers immediate value on first load: the Home tab populates a full, rich dashboard with 
no user input. Data is cached per session to avoid redundant scraping. Users are free to explore 
any movie, series, or franchise they like; they simply cannot re-fetch the exact same data set 
repeatedly within the same session.
Every view in CineStats supports one-click PDF report export — a fully formatted, visualization-rich 
document the user can download and save.

•
Present a unified Global + India perspective serving Indian audiences alongside 
international users.

Support Movie Detail views, Series/Franchise views (all entries, no internal limit), and TV 
Series views as separate first-class sections.
•
Allow cross-entity comparison of up to 10 movies, series, or franchises in the Compare tab. 
TV-to-TV comparison is separate; TV cannot be mixed with films.
•
Enforce session-level data caching to prevent scrape spam on the same view, while 
allowing free exploration of different entities.
•
Provide downloadable, visualization-rich PDF reports for any view.
•
Support multi-currency display with a persistent currency selector.
•
Be permanently free — no ads, no subscriptions, no paywalls, no data selling.

The Search tab provides a unified search experience across all content types in CineStats.

A prominent search input at the top of the tab. Searches as the user

Results are grouped into: Films, Series & Franchises, and TV Series —

12.4  Data Matching & Unification
•
Title normalization: lowercased, punctuation stripped, whitespace normalized before 
matching.
•
Fuzzy string matching (rapidfuzz library) to handle minor title discrepancies between 
sources.
•
Release date proximity matching within a configurable window (default ±7 days) to handle 
India vs global release gaps.
•
Manual override mapping table in SQLite for edge cases such as dubbed title variations.
•
A match confidence score is computed and stored; uncertain matches are flagged visually in 
the UI.

14   System Architecture
14.1  Data Layer
•
Scraper Modules: One module per source (bom_scraper.py, sacnilk_scraper.py, 
tvmaze_client.py, wikipedia_tv_scraper.py). Each returns a clean, typed pandas DataFrame.
•
Cache Registry: SQLite table scrape_cache stores (source, entity_key, scraped_at) to track 
what has been fetched in the current session.
•
Upsert Logic: All writes use INSERT OR REPLACE. Schema migrations handled by a 
versioned init_db.py script.
•
Exchange Rate Store: Session-level dict in Streamlit session_state. Not persisted to SQLite.
14.2  Business Logic Layer
•
TitleMatcher: Fuzzy-matching engine producing unified movie objects from BOM + Sacnilk 
records.
•
FranchiseGrouper: Auto-groups films into series using title pattern matching and a manual 
override table.
•
PredictorEngine: Historical-average model for opening weekend to lifetime gross projection.
•
ClashDetector: Groups films with the same release date for Clash Analyzer view.
•
MoverCalculator: Computes daily gross deltas for the Home movers section.
•
CurrencyConverter: Applies the session exchange rate to produce display strings in the 
selected currency.
•
PDFReportBuilder: Orchestrates ReportLab layout and kaleido chart image generation for 
export.
14.3  Presentation Layer
•
app.py: Main Streamlit entry point. Defines sidebar navigation and routes to page modules.
•
pages/: One module per tab (home.py, search.py, compare.py, tv_series.py, settings.py).
•
components/: Reusable UI components (movie_card.py, stat_bar.py, chart_wrapper.py,

14.4  Data Flow
1.
On first load of a tab or entity, Streamlit checks the scrape_cache table for a matching 
session entry.
2.
If no session entry exists, the relevant scraper is called. Rate-limiting delays are applied.
3.
Scraped data is cleaned, matched, and upserted into SQLite. The cache entry is written.
4.
Subsequent loads of the same view within the session read directly from SQLite — no re-
scrape.
5.
The user may freely navigate to different movies, series, or franchises; each triggers its own 
cache check.
6.
User interactions (search, filter, currency change, compare add/remove) operate on in-
memory DataFrames loaded from SQLite — no network calls.
7.
PDF export reads the current in-memory state, renders Plotly charts to PNG via kaleido, and 
builds the report with ReportLab — all locally.

16   Data Refresh & Caching Policy
Box office data is not updated continuously on source sites — figures typically update once daily or 
less. CineStats therefore applies a session-based caching policy rather than a time-based one, 
balancing data freshness with responsible scraping behaviour.
Session Cache
Each scraped entity is cached for the duration of the user session 
(identified by Streamlit session ID). The same entity will not be re-
scraped within the same session under any circumstance.
No Spam Refresh
Users cannot manually trigger a refresh of the same view/entity within a 
session. There is no refresh button on data views.
New Entity = New Fetch
Navigating to a different movie, series, or franchise always works 
freely. Each new entity gets its own cache entry and fetches fresh data 
if not already in SQLite.
Between Sessions
On a new session start, all prior session cache entries are treated as 
expired. Fresh scrapes occur for any entities loaded in the new 
session.
SQLite Persistence
Data fetched in prior sessions remains in SQLite and serves as a 
fallback if a live scrape fails. The UI shows a 'Last updated: [date]' label 
when serving persisted data.
Exchange Rates
Fetched once per session at startup and stored in session state. Not 
persisted to SQLite.

20   Scraper Contract & Output Schema
Each scraper module must conform to a defined contract. This ensures the business logic layer can 
consume any scraper's output without modification if a scraper is replaced.
20.1  Contract Rules
•
Each scraper exposes a single public function: scrape(entity_key: str) -> pd.DataFrame.
•
The returned DataFrame always contains the defined columns for that source, even if 
values are NaN for missing fields.
•
All string fields are stripped, lowercased, and normalized before returning.
•
All monetary fields are returned as Python float (not string). Currency symbols are never 
included in data fields.
•
All date fields are returned as Python date objects (not strings).
•
If a scrape fails for any reason, the scraper raises a ScraperException with a human-
readable message. It never returns partial data silently.

25   Legal & Ethical Considerations
•
Personal and Educational Use Only: CineStats is not intended for commercial redistribution. 
All scraped data is used solely for display and analysis within the application.
•
Robots.txt Compliance: All scrapers must check and respect the robots.txt of each source

Rate Limiting: A minimum delay of 2 seconds between consecutive requests to the same

User-Agent Headers: All HTTP requests must include an honest, descriptive User-Agent

Session Cache: The session-based cache directly limits the frequency of scraping. The

No PII Collection: CineStats does not collect, store, or transmit any personally identifiable

No Commercial Redistribution: Scraped data is used solely within CineStats. It is not sold, 
published, or shared via an API.

Monetization: CineStats is free forever with no advertising, no sponsored content, and no 
data monetisation of any kind.

Films currently running in cinemas — i.e., not yet finished their 
theatrical run.
Clash
Two or more films sharing the same theatrical release date and 
competing for audience share.
Holdover
A film's week-on-week retention of audience attendance. High holdover 
indicates strong word-of-mouth.
BOM
Box Office Mojo — primary global box office data aggregator, owned by 
IMDb/Amazon.
Sacnilk
Leading Indian box office tracking website covering Bollywood and all 
major regional industries.
TVMaze
A free REST API providing structured TV series, episode, and network 
data.
Upsert
Database operation: INSERT if the record does not exist, UPDATE if it 
does. Uses INSERT OR REPLACE in SQLite.
WAL Mode
Write-Ahead Logging — SQLite journaling mode that improves 
concurrent read/write performance.
Session Cache
A record in SQLite's scrape_cache table tracking what data has been 
fetched in the current Streamlit session, preventing re-scraping.
Franchise
A collection of films sharing a common cinematic universe, series, or 
brand (e.g. Marvel Cinematic Universe, Fast & Furious).
rapidfuzz
Python library for fast fuzzy string matching, used in the title matcher to 
align film names across sources.
